# Replacing Serein’s native calling backend with strict Swift

**Goal.** Ship Serein on macOS with its current Signal calling features and remove RingRTC, its Rust/C bridge, and the C++ WebRTC archive from the production call path. Keep the app-facing Swift API, signaling through SignalCore, and the existing `SignalCalling.xpc` boundary. The deliverable is the backend Serein needs to call stock Signal clients and join Signal group calls. A browser API, general-purpose SDP engine, arbitrary data channels, and ports to other operating systems are outside this plan.

**First interoperability milestone.** A Swift endpoint and an unmodified RingRTC endpoint place and answer a one-to-one call, exchange recognizable audio in both directions, and hang up. Repeat through a forced relay. This gives us a way to measure progress before taking on video or group calls.

## What counts as strict

Apply the following settings to every Swift target introduced for the rewrite, including generated Swift, tests, benchmarks, and platform adapters. Build debug and release with Swift 6 language mode. The calling manifest applies these settings to every Swift target, including tests and the service check executable. [Current package manifest](../Packages/SignalRingRTC/Package.swift)

```swift
let strict: [SwiftSetting] = [
    .strictMemorySafety(),
    .treatWarning("StrictMemorySafety", as: .error),
    .treatAllWarnings(as: .error),
]
```

CI should inspect the actual compiler invocations for `-strict-memory-safety` and `-warnings-as-errors`. Add compiler checks that accept safe code, reject an unacknowledged unsafe operation with the expected diagnostic, and reject an ordinary warning. Also test the source-policy check against an explicitly acknowledged unsafe operation. Swift accepts that last case even with both flags enabled. [Swift strict memory safety design](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0458-strict-memory-safety.md)

Extend Serein’s lint to cover the rewrite and its shipping dependencies. Reject explicit unsafe expressions, raw-pointer APIs, unchecked sendability, unaudited safety annotations, and diagnostic suppression. Inspect generated sources and transitive dependencies as well as the final link map. A Swift wrapper around libopus, libvpx, libsrtp, or the old dylib would still ship native calling code. Use bounded byte readers, checked arithmetic, and explicit limits on packet sizes, queue depth, frame dimensions, and per-call memory. [Existing safety lint](../Tools/lint-codecs.sh) · [Checked codec readers](../Packages/SignalCodecs/Sources/CodecCore)

**Platform boundary.** This plan trusts the Swift runtime and supported macOS APIs for sockets, device I/O, and cryptographic primitives. The calling protocols and media codecs themselves must satisfy the Swift policy. The current camera/screen pixel copy and Metal display upload use explicit `unsafe`, and the shared XPC transport has an unchecked sendability conformance. Track each one used by calls. Removing the native engine and achieving zero escapes across the entire call path are distinct milestones. [CaptureFrames.swift](../Packages/SignalUI/Sources/SignalUI/Video/CaptureFrames.swift) · [VideoTexture.swift](../Packages/SignalUI/Sources/SignalUI/Video/VideoTexture.swift) · [XPCTransport.swift](../Packages/SignalMediaService/Sources/MediaXPCInterface/XPCTransport.swift)

## Implementation sequence

### 1. Establish the reference and prove the platform interfaces

Pin the test peer to RingRTC 2.76.0 and Signal WebRTC `8037f` (`6a9ba305`). Map each command and event used by Serein to its app caller, wire behavior, and acceptance test. Record which codecs, relay transports, packet extensions, and optional features the macOS build actually negotiates. Mark an item deferrable only when an interoperability test demonstrates the supported fallback and the app keeps its behavior. [Commands](../Packages/SignalRingRTC/rust/src/commands.rs) · [Events](../Packages/SignalRingRTC/rust/src/events.rs) · [Pinned C++ interface](https://github.com/signalapp/webrtc/tree/6a9ba30543831d959be0cddf67486c7511455dcb/ringrtc/rffi/src)

Make the service’s endpoint factory injectable. The app already uses an endpoint protocol, but the service stores concrete `NativeEndpoint` instances and calls their raw JSON methods. Adapt that service-side interface and run its existing tests against the native default before adding Swift behavior. Give the harness independent backend selection for each peer, synthetic PCM and video frames, a controllable clock and network, and a test TURN server. Capture baseline setup time, audio delay and gaps, video rate, CPU, and peak memory on the same Mac. Set regression limits from those measurements. [Endpoint contract](../Packages/SignalRingRTC/Sources/SignalRingRTC/Endpoint.swift) · [Service handler](../Packages/SignalRingRTC/Sources/CallService/CallXPCHandler.swift) · [Loopback harness](../Packages/SignalRingRTC/Tests/SignalRingRTCTests/LoopbackCallTests.swift)

In parallel, compile and exercise the smallest real macOS adapters under the strict settings and existing sandbox. Try UDP send/receive, microphone capture and speaker playout, camera/screen frame access, display, and the key operations each wire protocol needs. The voice-note recorder already demonstrates a safe microphone read. Playout and pixel transfer need their own demonstrations. Record any unavailable SDK operation and the affected feature before committing to a device design. Synthetic media lets protocol work proceed while a device issue is open. [Microphone example](../Packages/SignalMediaService/Sources/VoiceNoteService/VoiceNoteRecorder.swift) · [Existing PCM write](../Packages/SignalUI/Sources/SignalUI/Audio/PCMBuffer.swift) · [Sandbox profile](../Packages/SignalMediaService/Sandbox/SignalCalling.sb)

### 2. Make a direct Signal call possible

Implement bounded readers and writers for Signal’s V4 offer/answer protobuf, V3 ICE candidate additions and removals, and call-control messages carried over RTP. Port the direct-call state transitions for ringing, accept, busy, decline, hangup, and multi-device answers. Implement the identity-bound key agreement and directional SRTP/SRTCP protection. Compare both roles with fixed test identities and keys, including invalid keys, altered packets, replay, and sequence-number wrap. Signal specifies discrete V4 fields and derives media keys using its signaling exchange. This is the reason browser JSEP, SCTP data channels, and a general DTLS handshake are absent from the critical path. [Signaling versions](../vendor/ringrtc/src/rust/src/core/signaling.rs) · [Wire schemas](../vendor/ringrtc/protobuf/protobuf) · [Direct-call key derivation](../vendor/ringrtc/src/rust/src/core/connection.rs)

Implement the ICE, STUN, and TURN behavior exercised by Serein’s relay configuration. Cover candidate gathering, connectivity checks, nomination, consent, allocation refresh, relay failure, and network changes. Keep the app’s `hideIp` decision for both “Always relay calls” and untrusted contacts. **Pass when** Swift and native peers agree on keys and exchange authenticated control packets in both roles. In relay-only mode, inspect both the advertised candidates and the actual packet destinations. Relay failure must end or fail the call without exposing a direct path. [Relay selection](../Packages/SignalCore/Sources/SignalCore/Calling/CallingService.swift) · [RTP control messages](../vendor/ringrtc/protobuf/protobuf/rtp_data.proto)

### 3. Deliver one-to-one audio

Build a strict Swift Opus encoder and decoder for the negotiated Signal modes. Use reference Opus vectors and cross-decode in both directions. Add packet timing, jitter buffering, packet-loss concealment, resampling, and clock-drift handling. Exercise mute, warm-up, route selection, audio levels, echo control, and device changes. Check the configured Opus DRED loss-recovery behavior where Serein enables it. [Calling codec](../Packages/SignalRingRTC/Sources/SwiftCalling/OpusSpeechDecoder.swift) · [Optional calling assets](../Packages/SignalCore/Sources/SignalCore/Calling/OptionalResources.swift)

**Pass when** both peers recognize the injected audio at their decoded PCM outputs in direct and forced-relay calls, with each side originating once. Score timing, gaps, and distortion against the baseline under repeatable loss, jitter, and reordering. Then repeat with real devices and a stock Signal client.

### 4. Add camera video and screen sharing

Start with bidirectional VP8. The existing WebP implementation handles VP8 still images. Live interframes, encoding, RTP packetization and reassembly, keyframe requests, loss recovery, pacing, bandwidth adaptation, and A/V sync need separate work. Add VP9 and the scalable layers required by Serein’s negotiated group and screen-sharing modes. Direct calls enable VP9 encode and decode by default. Inventory other advertised codecs by direction before scheduling them. Reuse existing Swift pixel or codec code where vectors and timing measurements support it. [Video settings](../Packages/SignalRingRTC/Sources/SignalRingRTC/RingRTC.swift) · [WebP codec](../Packages/SignalCodecs/Sources/ImageWebP)

**Pass when** a stock peer and Swift each receive a known moving image and a legible shared screen. Verify dimensions, colors, orientation, delay and recovery after packet loss. Switch camera, mute video, start and stop sharing, revoke capture permission, and end the call during capture. Run Serein’s capture model against the production path. [Video loopback](../Packages/SignalRingRTC/Tests/SignalRingRTCTests/LoopbackCallTests.swift) · [Capture verification](../Verification/CallCapture/README.md)

### 5. Deliver group calls and call links

Implement the client for Signal’s selective forwarding unit (SFU). Cover join, peek, leave, reconnect, participant-to-stream mapping, video subscriptions, and reliable control messages. Implement both the SRTP hop to the SFU and Signal’s end-to-end frame encryption between devices, including key distribution, rotation, resend, and membership changes. Preserve app-mediated SFU HTTP, recipient restrictions, and the existing ownership of account credentials. Trace RingRTC’s endorsement verification explicitly and cover it with fixtures before removing its dependency. [Group protocol](../vendor/ringrtc/src/rust/src/core/group_call.rs) · [Frame crypto](../vendor/ringrtc/src/rust/src/core/crypto.rs) · [Endorsements](../vendor/ringrtc/src/rust/src/core/endorsements.rs)

Exercise group ringing, mute controls, raised hands, reactions, presenting, admission and removal. Cover call-link creation, lookup, editing, restrictions, revocation, and deletion. Reuse Serein’s Swift call-link root keys. **Pass when** a Swift participant exchanges audio and video in a mixed three-device call through a compatible SFU, and a late joiner and a removed participant receive exactly the media their key epochs permit. Run this for both a Signal group and a call link, including link-admin actions. [App group integration](../Packages/SignalCore/Sources/SignalCore/Calling/CallingService+Group.swift) · [Call links](../Packages/SignalCore/Sources/SignalCore/Calling/CallLinks.swift) · [Swift root keys](../Packages/SignalRingRTC/Sources/SignalRingRTC/CallLinkRootKey.swift)

### 6. Switch production and retire the native build

Throughout implementation, add each new wire parser and codec to a bounded-input fuzz harness. Save cases that produce crashes, traps, excessive allocation, or missed media deadlines as regressions. Review key derivation, replay handling, group key changes, and relay privacy against independent reference vectors and mixed-peer tests before enabling the corresponding call type.

Run the new backend first in test builds behind the same XPC service. Pin the backend for the lifetime of a call. During trials, rollback selects the known native build for a subsequent call. Exercise stock Signal Desktop, iOS, and Android peers, Swift-to-Swift calls, long sessions, sleep/wake, network changes, loss, and service restart. Require the app’s recipient checks, stale-generation rejection, idle retirement, and microphone/camera shutdown to pass. Run the Lean conformance rigs with their oracles present and exercise the packaged service under its actual sandbox. [Call boundary](../Verification/CallBoundary/README.md) · [QA commands](../QA.md)

Once the feature matrix and quality limits pass, change the shipping factory, remove the Rust/C bridge and RingRTC/WebRTC fetch, link, copy, and signing steps from the production build. Build a signed app from a clean checkout with the native calling artifacts absent. Inspect SwiftPM dependencies, link maps for static archives, dynamic load commands, and the bundle contents. Keep the pinned native peer separately buildable for interoperability tests. Update the build checks and README to describe what actually ships. [Packaging and isolation checks](../Tools/build-app.sh) · [Native build script](../Tools/build-ringrtc-ffi.sh)

## Implementation status

The signed app uses the Swift backend on normal launch for direct calls, group calls and call links, including after an XPC service restart. Its calling service instantiates the Swift engine for both current and legacy creation requests. Native RingRTC runs in separately built interoperability fixtures. [App endpoint](../App/SignalSafe/Sources/SignalSafe/Calls.swift) · [Production service](../Packages/SignalRingRTC/Sources/SignalCallingService/main.swift)

RingRTC 2.76.0 lets iOS peers opt into hardware H.265 for direct calls. Serein negotiates VP8 or VP9 from the peer’s advertised codecs. This release preserves the signaling format and SFU protocol. [Upstream changelog](../vendor/ringrtc/CHANGELOG.md#v2760) · [Swift codec negotiation](../Packages/SignalRingRTC/Sources/SwiftCalling/LiveVoiceSession.swift)

### Open compatibility checks

- On the built-in MacBook Pro speaker and microphone, with output unmuted at 31%, the two unprocessed echo levels were −87.3 and −86.0 dBFS. Both were below the probe’s −70 dBFS minimum for measuring attenuation. Physical echo reduction remains unverified. The synthetic delayed two-path test measured 39.9 dB of reduction. [Acoustic probe](../Tools/calling-safety/ProbeEcho.swift)
- Calls to stock Signal Desktop, iOS and Android clients, physical network changes, and sustained calls on two devices still need verification.
- Engine-specific raw diagnostics still differ. WebRTC exposes its internal encoder quality-limitation reasons and audio-processing debug counters. Serein’s app does not request raw group statistics. [Group diagnostics test](../Packages/SignalRingRTC/Tests/SignalRingRTCTests/GroupCallInteropTests.swift)

The mixed group test supports scalable VP9 in both directions. Set `SEREIN_TEST_NATIVE_SVC=1 SEREIN_TEST_SWIFT_SVC=1` to exercise camera and screen sharing, and add `SEREIN_TEST_VIDEO_LAYERS=1` to require the native receiver to display the full 640×360 Swift picture. `SEREIN_TEST_VIDEO_LAYERS=3` feeds a 1280×720 source to exercise three spatial layers.

Run `Tools/qa.sh lint:calling calling:speech calling:speech-relay calling:turn-streams calling:sfu` with the pinned reference, coturn and local SFU installed. The optional network suites require their fixtures. The ordinary SwiftPM test count alone does not exercise all transports.
